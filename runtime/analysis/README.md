# runtime/analysis — the offline data-analysis sandbox runtime

The pinned, offline Python image for the **analysis** task profile (doc 40 Stage 3 hero task:
"find the worst-performing region and give me a chart"; research/42 C29/C32). It also carries the
bounded **output collector** (`runtime/outputs/collect_outputs.py`) and is the collector image for
the Node profile too. Nothing here is a judge: everything the sandbox prints or writes is untrusted
data that the supervisor bounds and the controller validates (CLAUDE.md §3).

```
runtime/analysis/build.sh          # -> airlock-runtime-analysis:dev; prints {imageId, sizeBytes, ...}
runtime/analysis/demo.sh           # real Docker, runc = DEV-UNSAFE; 29 PASS lines expected
```

## Runner contract (analysis and Node profiles share it)

| Path | Who writes it | Notes |
|---|---|---|
| `/workspace/inputs/` | the supervisor, before any model step | copies of controller-owned input artifacts (uploads, browser downloads), streamed in as uid 1000 via `docker exec -i` (no `docker cp`, no bind mounts), then `chmod 0444` files / `0555` dir. The model *could* chmod them back (same uid); that is harmless because the controller keeps the authoritative copy and digest, and nothing is ever collected from `inputs/` |
| `/workspace/code/` | the supervisor, with the model's code | `code/<path>.py` (analysis) or `code/<path>.mjs|.js|.cjs` (Node), ≤ 5 directory levels |
| `/workspace/outputs/` | the model's code | the **only** directory ever collected |
| cwd | `/workspace` | enforced by `run.sh` |

Execution is always the fixed runner, never a model-chosen command line:

```
docker exec -u 1000:1000 -w /workspace <c> timeout <s> /opt/airlock/run.sh code/analyze.py
```

`run.sh` validates the script path, prepares `/tmp/matplotlib`, and execs `python3 -E -s -B`
(ignores `PYTHON*` env, no user site, no bytecode writes; the script's directory stays importable so
the model can split code into modules). The supervisor bounds wall time and stdout/stderr bytes.
The container has `--network none`, so there is no package installation of any kind; pip is also
physically absent (proved in `demo.sh`).

Sandbox flags (the supervisor's, reproduced by `runtime/outputs/demo-lib.sh`):
`--network none --read-only --cap-drop ALL --security-opt no-new-privileges --user 1000:1000
--pids-limit 128 --memory 1g`, `/tmp` = `rw,nosuid,nodev,noexec,size=64m` tmpfs, `/workspace` = the
attempt's `local` volume backed by a `size=128m,uid=1000,gid=1000,mode=0755` tmpfs.

## Collection

See `runtime/outputs/README.md`. In short: provision a fresh collector container from **this**
image with the attempt volume at `/candidate:ro` (this holds the tmpfs volume), stop + confirm the
author, probe the collector, then
`env -i python3 -I -S /opt/airlock/collect_outputs.py --root /candidate` with cwd `/`.
