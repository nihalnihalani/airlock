1. What Airlock is

Tagline: Let the agent do anything. Nothing it does can touch you.

Airlock is built for Challenge 1 at The Agent Arena Hackathon (Vultr, San Francisco, Sep 2026): a web agent that performs real work — writing and running code, or driving a real browser — where every action is contained in a sandbox on Vultr, and a central control layer plans, dispatches, and returns verifiable output.

Two task kinds, one control plane

KindWhat it doesHow success is decided
Repair Takes an untrusted bug report for a supported library (hero: tabulate-365 / python-tabulate #365), reproduces the failure, attempts a minimal repair, returns a patch. External comparator on sealed candidate bytes in fresh sandboxes. Outcomes include CANDIDATE_PASSED_CHECKS, CHECKS_FAILED, NOT_REPRODUCED, etc.
General Profiles analysis, web-research, web-analysis: Chromium, offline Python/Node, uploads, screenshots, human takeover, digest-bound form approvals. Controller-owned completion checks on collected outputs/evidence (RESULT_VERIFIED / RESULT_PARTIAL / …).
The agent cannot mark its own homework. A forged “all tests passed” log still fails. “Passed these checks” means exactly the frozen cases passed — not safe, certified, or generally correct.

Repair loop (phases)

prepare → baseline → reproduce → repair → freeze → verify → ready

  • Baseline / verify: one fresh one-shot sandbox per contract case.
  • Freeze: revoke → stop → collect allowed files → seal SourceManifest.
  • submit_candidate: only advances to freeze; does not mean pass.

Adapted modules from OpenMuse (worker, store patterns) and OpenBot (narrow supervisor). Neither upstream app is the composition root; CopilotKit / AG-UI are not dependencies. Pins and modifications are recorded in THIRD_PARTY_NOTICES.md.

4. Trust model & checkpoints

Standing invariants (CLAUDE.md §3)

  1. One authority per concern — controller, supervisor, comparator, artifacts; model owns none.
  2. Untrusted code only in its sandbox — report text, generated code, candidate library never run on VM A.
  3. Candidate identity is immutable — verify / preview / export share one sealed digest.
  4. Worker cannot declare success — sandbox exit codes and forged logs carry no authority.
  5. Cancellation has an execution effect — revoke → stop → confirm → fence late results.
  6. Ownership checked at every access — IDs are not bearer tokens.
  7. No secrets / network / host in code sandboxes — browser reaches only its allowlisting egress proxy.
  8. Runtime tier inspected, never assumed — Kata target; gVisor floor; runc is dev-unsafe only.
  9. Five checkpoints on every run record.
  10. All runtime model calls go through Vultr Serverless Inference.

The five checkpoints

#CheckpointProves
1Host checkCPU virt, /dev/kvm, runtimes, selected runtime, not dev-unsafe
2Execution logEvery command with exit code, duration, bounded output
3In-sandbox identityhostname + uname from inside (Kata guest ≠ host)
4Isolation probemetadata · DNS · TCP · Docker socket · mounts all BLOCKED before agent work

6. Worker, Store & Supervisor

These three pieces form the durable orchestration spine. The Store remembers; the Worker drives tasks from that memory; the Supervisor is the only place that actually executes. 

UI / API  →  Store (PGlite on VM A)
                ↑↓
            TaskWorker  →  RepairHandler / GeneralHandler
                                ↓ journaled HTTP over VPC
                          Supervisor (VM B, Docker/Kata)

The model and handlers never touch Docker. The supervisor never owns task identity or outcomes.

6.1 Store — apps/control/src/store

Control-plane database on VM A, adapted from OpenMuse’s db.ts, running PGlite (Postgres-compatible, in-process).

Tables

TableRole
records Generic JSON documents keyed by (owner, kind, id) — tasks, manifests, grants, worker status
events Append-only run log with per-task monotonic seq (SSE replay via Last-Event-ID)

Key write paths

  • put — upsert (mutable things like task progress).
  • compareAndSwap — atomic claim/update only if expected fields match (leases, approvals).
  • insertImmutable — insert-or-refuse; used for verification records, manifests, export grants (no overwrite).
  • appendEvent / listEvents — durable, ordered event stream.
  • scanWhere — worker polling by status without loading every record.
Ownership is first-class: every record is scoped to an owner. Task IDs are not bearer tokens; cross-owner access reads as 404. Generic upsert is forbidden for artifacts — immutable identity is a trust invariant.

6.2 Worker — apps/control/src/worker

TaskWorker is the durable lease loop on VM A, adapted from OpenMuse’s engine/worker.ts. It does not know how to repair or browse — it only claims work and calls a TaskHandler.

Tick cycle (~1s)

  1. Scan Store for queued, expired-lease running, or cancelling tasks.
  2. CAS-claim with a fresh leaseId + leaseUntil.
  3. Invoke the handler with a TaskContext:
    • mode: "run" or "cancel"
    • guard() / checkpoint() — throw LostLeaseError if the lease is gone
    • event() — append to Store’s event log
  4. Heartbeat renews the lease while the handler runs.
  5. On finish: clear lease, apply the handler’s terminal patch.

Handlers plugged at startup

HandlerRole
RepairHandler Deterministic phases: prepare → baseline → reproduce → repair → freeze → verify → ready
GeneralHandler Browser/code tools + controller-owned completion checks

Cancellation

Not a DB flag alone. The API sets cancelling → worker runs cancel mode → revoke/stop/confirm on the supervisor → only then cancelled. Unconfirmed teardown stays cancelling and retries (bounded); past the bound the task is recorded failed with an honest unconfirmed teardown — never a forged cancelled.

6.3 Supervisor — apps/supervisor

Narrow HTTP service on VM B — the only process with the Docker socket. Forked from OpenBot’s supervisor idea, extended with execution, freeze, invoke, fencing, capacity, and janitor.

The real boundary

A bearer token keeps strangers off the port. The API vocabulary is the wall: callers can say create attempt / run tool / freeze / revoke / destroy — never “use this image / mount / network / runtime / host path,” because those are not expressible in the API.

Local journal (SQLite on VM B)

Separate from the control Store. Guarantees:

  • Operation id + request digest → replay the same result, or conflict if digest differs.
  • Pending ops after a crash become interrupted, never a forged receipt.
  • Generation fencing — stale or revoked generations get 409 before every exec.

Lifecycle

create → inspect hardening → isolation probe → tools → freeze → destroy

Freeze ordering: revoke → provision collector with volume read-only → stop author → settle outstanding execs → collect. Host capacity admission returns 429 before any Docker call if the budget is full.

Main routes

RoutePurpose
POST /attemptsCreate disposable attempt (author / hostile / …)
POST …/toolBounded read / write / exec inside the attempt
POST …/renewExtend renewable execution authorization
POST …/freezeStop and collect sealed file envelope
POST …/revoke · /destroyStop authority; remove container + volume
POST /invokeFresh one-shot verify/baseline/preview sandbox
POST /hostileContainment demo (rm -rf / fork bomb) with survival card
GET /host · /capacity · /listingHost check, admission budget, host-wide inventory

Sandbox roles

author, one-shot invoke roles (baseline / candidate / preview), hostile, analysis, node, plus browser + egress pair. Code roles use --network none; the browser reaches only its per-attempt egress proxy.

7. How the three pieces fit together

PieceOwnsNever
Store Task identity, leases, events, sealed artifacts on VM A Execution or Docker
Worker Claiming, heartbeats, cancel retries, calling handlers Declaring pass/fail or creating containers
Supervisor Containers, deadlines, isolation, cleanup on VX1 Trusting caller-chosen mounts/images, or deciding task outcomes

Handlers (Repair / General) sit between Worker and Supervisor: they read and write the Store through the worker context, and every supervisor mutation is journaled on the control side before the HTTP call goes out. Crashes surface as unknown / interrupted, never as invented receipts.
